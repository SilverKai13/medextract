## 2026-08-20 — First full end-to-end run

The project's entire prior history was "written and tested offline, never run".
This is the run.

**Machine.** Windows 11, AMD Ryzen 7 5800H (8C/16T), 16 GB RAM, NVIDIA RTX
3050 Ti Laptop with **4 GB VRAM**, driver 566.07 / CUDA 12.7, Python 3.13.5,
torch 2.6.0+cu124, onnxruntime 1.26.0. Full detail in
[ENVIRONMENT.md](ENVIRONMENT.md).

### Before anything ran

Twelve defects had to be fixed first — six found by inspection, four during
setup, and two by reading what the finished system actually produced. Full
write-ups in [BUGS.md](BUGS.md). Four failed silently.

The blockers alone: the documented `load_dataset` call no longer works at all,
BioBERT lowercases its own cased vocabulary, MLflow 3 refuses the file store,
and a stray TensorFlow install breaks `Trainer` at import.

### Training — 9-arm sweep

`python -m medextract.sweep`, ~40 minutes wall clock, all nine arms completed,
no OOM, no failed arm.

Corpus source: `hub-parquet (ncbi/ncbi_disease@refs/convert/parquet)`.
Splits 5433 / 924 / 941.

Full table: [sweep_table.md](sweep_table.md), generated by `report.py` from the
tracking store.

| | validation F1 | test F1 |
|---|---|---|
| Best | **0.8818** (PubMedBERT) | **0.8838** (BioBERT, seed 1337) |
| Worst | 0.8520 | 0.8702 |
| Target | ≥ 0.85 | ≥ 0.85 |

**Every arm cleared the target.** But the interesting content is what the
seed repeats say about all the other differences.

#### What the sweep actually established

Three findings, all in [RESULTS.md §2](RESULTS.md#2-training) with the
supporting tables:

1. **Seed noise is 0.0061 validation F1** — seven entities out of 787 — from
   nothing but initialisation and data order.
2. **No hyperparameter in the BioBERT grid clears that bar.** All eight arms sit
   in a 0.0111 band. The subword convention, which got its own arm to settle
   [ADR-002](DECISIONS.md#adr-002), moves F1 by 0.0004.
3. **PubMedBERT is the one real effect**, +0.0187 over the best BioBERT arm,
   improving precision and recall together.

And two cautions that matter more than the headline: validation and test F1 are
**negatively** correlated (r = −0.399), and validation loss carries essentially
no information about entity F1 (r = −0.001). Both are unpacked in
[RESULTS.md §2.7](RESULTS.md#27-two-cautions-on-reading-this-table).

The sweep's job was to make a 0.005 gap readable. It did — by showing that
almost every gap in the table is one.

### ONNX export and parity

Exported the arm `select_best_arm` chose (highest validation F1: PubMedBERT).
Parity passed on all three levels — max logit difference **1.48e-05** against a
1e-4 tolerance, argmax agreement **1.0000**, decoded spans **identical**.
Independently reproduced on a second arm at 7.87e-06 while de-risking the step
before the sweep finished.

Full figures: [RESULTS.md §3](RESULTS.md#3-onnx-export-and-parity).

### Latency

**2.72× at batch 1, 1.32× at batch 16** (p50, CPU only). Batch 1 lands inside
the 2–4× the README predicted; batch 16 does not, which is exactly why the
instruction was to measure rather than quote the range.

Full percentile distribution and the reason the gain shrinks with batch size:
[RESULTS.md §4](RESULTS.md#4-latency).

### Retrieval

3,000 abstracts fetched through E-utilities and indexed into Qdrant with the
real ONNX encoder — the hashing fallback was refused, as designed. 1,191 of
them were structured abstracts, reassembled with their section labels rather
than truncated to the first section.

Corpus statistics, index configuration and sample queries:
[RESULTS.md §5](RESULTS.md#5-retrieval).

### Container

**395 MB** against a 1,500 MB budget, with torch, datasets and mlflow verified
absent inside the image. The README's ~560 MB estimate was too high because it
added a 390 MB dependency measurement to a 150 MB base that already provides
the Python runtime those dependencies sit on — corrected in place, with the
reasoning kept.

Full breakdown: [RESULTS.md §6](RESULTS.md#6-serving-container).

### Live verification

Every endpoint exercised against the running container, including the degraded
path with no model mounted (200 `degraded`, then 503 with an actionable
message), character offsets on non-ASCII input, batch/single equivalence, and
the 413/422 bounds. The README's documented `/extract` example now returns
literally what the README says it does.

Table of checks: [RESULTS.md §6.1](RESULTS.md#61-live-endpoint-verification).

### Tests and lint

**202 tests, 1 skipped, offline, 26 s.** `ruff check` and
`ruff format --check` clean. Started from 163 — and those 163 were all failing
to import, because the package was not installed. The 39 added cover the twelve
defects.

## What this run changed about the project's claims

1. **The result tables hold measured numbers.** Every `TODO` is gone, and all
   of them were replaced by scripts rather than typed.
2. **The reported F1 now predicts served output.** Before [B11](BUGS.md) was
   fixed, evaluation scored first subwords while `/extract` decoded every
   subword, so a 0.88 F1 sat alongside spans like `"ne"` and `"rot"`. They now
   measure the same thing.
3. **The sweep's conclusion is mostly negative, and that is the useful part.**
   Eight of nine arms are indistinguishable. Reporting that is worth more than
   presenting a 0.005 gap as a finding.
4. **Estimates that turned out wrong were corrected in place**, with the reason
   kept — the image size, and the batch-16 speedup falling outside the
   predicted range.
